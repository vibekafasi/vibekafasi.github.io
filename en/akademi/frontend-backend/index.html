Frontend, backend and database

What are the frontend, the backend and the database? Learn the three layers of an app with a restaurant analogy, and which projects need which.

Lesson 4/66 min readUpdated: November 2026

When working with AI, you'll hear the words “frontend,” “backend” and “database” a lot. These are the three layers of an app. If you know what each layer does, you'll write clearer prompts and avoid unnecessary complexity.

The restaurant analogy

Picture a restaurant. The dining room is what the customer sees: tables, menu, decor. That's the frontend. The kitchen is where the food is made, out of the customer's sight. That's the backend. The pantry and order book are where ingredients and records are kept. That's the database. There's also a waiter carrying orders between the dining room and the kitchen; you'll meet them in the next lesson under the name API.

Frontend: what the customer sees

The frontend is the part that runs on the user's screen: the page layout, buttons, forms, colors. It's built with HTML, CSS and JavaScript and runs in the user's browser. An important detail: frontend code is sent to the user's computer. That means anyone who wants to can open it and read it. On any site, press Ctrl + U (on Mac Cmd + Option + U) to see the page's source code.

Backend: the kitchen

The backend is the program that runs on the server and that the user can't see. It checks the user's login details, saves the order, connects to the payment service, sends emails. It's usually written in JavaScript (with Node.js), Python or another language. Secrets, like passwords and API keys, can only be kept safe here.

Database: the pantry and order book

A database is a system that stores information in an organized, permanent way. You can think of it as a very smart spreadsheet with many tabs: a “Customers” tab, an “Orders” tab, a “Products” tab. Each row is a record, each column a piece of information. The difference: a database can handle thousands of people reading and writing at the same time, and it finds what you're looking for very fast. Common examples are SQLite, PostgreSQL and MySQL.

FrontendDining room and menuIn the user's browserEveryone
BackendKitchenOn the serverOnly you and authorized people
DatabasePantry and order bookOn the server or in a database serviceOnly the backend and authorized people

The journey of an order

  1. The customer picks a product in the frontend and clicks the Place order button.
  2. The frontend sends the order details to the backend.
  3. The backend checks the details: is the product in stock, is the total correct?
  4. The backend saves the order to the database.
  5. The backend replies “OK” to the frontend, and the customer sees “Your order has been received” on screen.
Watch out

Golden rule: everything you put in the frontend is public. Never let an API key, database password or any secret be written into frontend code. And don't leave checks like price and stock only in the frontend; someone with bad intentions can change the frontend, so the backend must do the final check.

Not every project needs all three

  • Frontend only: A profit calculator, a landing page, a simple game. If no information is stored, there's no need for a backend.
  • Frontend plus a ready-made service: For small needs like a contact form, you can use ready-made form or database services instead of writing your own backend.
  • All three layers: Things like user login, order tracking and a customer dashboard. You should take these on only after finishing the course's security module (Module 6).
Tip

When writing a prompt for AI, say which layer you're working on: “Frontend only: change the button's color,” for example. That keeps it from touching places it shouldn't.

Key takeaways

  • The frontend is the dining room, the backend the kitchen, the database the pantry and order book.
  • Frontend code is public; secrets live only in the backend.
  • Not every project needs three layers; start with the simplest version.

Test yourself

3 quick questions. Pick an answer and see the right one instantly.

1Where should an API key be kept?

Frontend code goes to everyone's browser and can be read. Secrets stay safe only in the backend.

2What does a tool need if it only calculates profit from the numbers you enter and stores nothing?

The calculation can happen in the browser, and since nothing is stored, there's no need for a backend or a database.

3In the restaurant analogy, what does the database correspond to?

The database is where information is stored in an organized, permanent way, just like a pantry and order book.
