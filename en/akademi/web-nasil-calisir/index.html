How does a website work? (browser, server, domain)

What happens behind the scenes when you type a site into the address bar? Learn browsers, servers, domains, DNS and HTTPS step by step with a mail analogy.

Lesson 3/66 min readUpdated: November 2026

When you type an address into your browser and press Enter, a lot happens in less than a second. Knowing this will help you a lot later, when you put your own site online and when you solve “the site won't open” problems.

The four main players

  • Browser: Programs like Chrome, Safari, Edge and Firefox. It's the side that requests web pages and shows them on screen.
  • Server: A computer that is always online, stores the site's files and answers incoming requests.
  • Domain name: An address people can remember, like vibekafasi.github.io.
  • DNS: The system that turns a domain name into the numeric address computers understand, the IP address.
The mail analogy

You want a catalog from a shop, but you only know the shop's name. First you look it up in the directory to find the shop's street address; that's DNS. Then you write a letter to that address saying “Could you send me your catalog?”; that's the request. The shop, the server, puts the catalog in an envelope and mails it back; that's the response. Then you open the envelope and spread the catalog on the table; that's what the browser does.

What happens when you press Enter

  1. The browser gets the IP address of the domain you typed from DNS.
  2. It sends a request to the server at that address: “I want this page.”
  3. The server sends the page's files back as a response: HTML, CSS, JavaScript and images.
  4. The browser checks the list in the HTML and sends new requests for the missing pieces.
  5. Once all the pieces arrive, the browser puts them together and draws the page on screen.

HTTP, HTTPS and the padlock icon

The browser and server talk in a shared language called HTTP. The S in https:// at the start of an address stands for “secure.” With HTTPS, the information traveling between them is encrypted; even if someone listens in, they see meaningless characters. The padlock or settings icon in the address bar shows the connection is encrypted. But careful: an encrypted connection doesn't mean the site is honest; a fake site can use HTTPS too.

The server's response codes

The server puts a three-digit status code at the start of every response. Knowing these codes lets you give AI the right information when debugging.

CodeMeaningIn plain words
200OKHere you go, this is what you asked for.
301 / 302RedirectWe've moved; here's our new address.
404Not FoundThere's no such page.
403ForbiddenYou're not allowed in here.
500Internal Server ErrorSomething went wrong in the kitchen.

Static and dynamic sites

A static site sends everyone the same files; it's like a brochure. Landing pages, portfolios and course pages like this one are usually static and can be published for free. A dynamic site builds the page for each visitor on the spot, like a shopping site that shows your orders when you log in. Dynamic sites have a program running behind them and usually a database. You'll see this in the next lesson.

See behind the curtain with your own eyes

  1. Open any site you like in Chrome or Edge.
  2. Press F12 (on Mac Cmd + Option + I) and switch to the Network tab in the panel that opens.
  3. Reload the page (F5, on Mac Cmd + R). Every request the browser sends shows up one by one in the list: HTML, CSS, images…
  4. Look at the Status column of the first row in the list; you'll most likely see 200.
  5. Also try adding /no-such-page-123 to the end of the site's address in the address bar and pressing Enter. Most sites show a 404 page.
Tip

When you describe a site problem to AI, include the status code: saying “The page returns 404” instead of “The page won't open” gets the problem solved much faster.

Key takeaways

  • The browser asks, the server sends; DNS turns the domain name into a numeric address.
  • HTTPS encrypts the connection, but on its own it doesn't prove a site can be trusted.
  • 200 means all good, 404 means no such page, 500 means a problem on the server.

Test yourself

3 quick questions. Pick an answer and see the right one instantly.

1What is DNS's job?

DNS is like a directory: it turns the domain name people remember into the IP address computers use.

2When you try to open a page, you get a 404 code. What does that mean?

404 says the server couldn't find a page at that address. Program errors are usually shown as 500.

3What does seeing the HTTPS padlock in the address bar guarantee?

HTTPS only shows that the information on the way is encrypted. Fake sites can use HTTPS too.
